# Claude Code Statusline

A statusline for [Claude Code](https://claude.com/claude-code) that shows, at a glance: account, directory, git branch, model, effort level, context window usage, rate limits, session time, token burn rate, platform incidents, and your last prompt.

```
👤 marty  📁 ~/code-projects/app  🌿 main  🤖 Fable 5.1  ⚡ high
🧠 [===------------] 21% 1M  🚦 5h 12%  7d 34%  📟 v2.1.319 ✓
→ Add a retry to the upload worker and log the attempt count
```

Generated with [`@chongdashu/cc-statusline`](https://www.npmjs.com/package/@chongdashu/cc-statusline), then extended by hand (see [What's Custom](#whats-custom)). The whole thing is one bash script: [`statusline.sh`](statusline.sh).

---

## Quick Install

### Step 1 — Install `jq`

Required by the installer and by most of the script's JSON parsing.

```bash
# Mac
brew install jq

# Ubuntu / Debian
sudo apt install jq
```

### Step 2 — Install the script

```bash
git clone https://github.com/MartyBonacci/claude-code-statusline.git
cd claude-code-statusline
./install.sh
```

This copies `statusline.sh` to `~/.claude/statusline.sh` and adds this to `~/.claude/settings.json` (merging with whatever is already there):

```json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "padding": 0
  }
}
```

An existing script is backed up first. If `settings.json` already points `statusLine` at something else (for example a wrapper that calls this script), the installer leaves that alone; pass `--force` to replace it.

Prefer to keep editing the script under git? `./install.sh --link` symlinks `~/.claude/statusline.sh` to the clone instead of copying it.

### Step 3 — Restart Claude Code

The statusline appears at the bottom of every session.

## What's Custom

The script was generated by `cc-statusline` with these features: `directory, git, model, context, usage, session, tokens, burnrate`. Three things you see in the live demo are **not** from the package — they were added by hand after generation:

**⚡ Effort level** — reads `effortLevel` directly from `~/.claude/settings.json` and colors it by urgency (blue → gold → coral as you go low → medium → high).

**👤 Account email prefix** — calls `claude auth status`, caches the result keyed by a fingerprint of your access token so it only re-fetches when you log in or out.

**→ Last prompt** — reads the `transcript_path` from Claude Code's JSON input, finds your most recent user message, and truncates it to fit the terminal width. It's the thing that makes the statusline feel like a "now playing" indicator.

**⚠ Platform status alert** — polls `https://status.claude.com/api/v2/summary.json` every 5 minutes in the background (never blocks). Shows the active incident title in gold/coral/red depending on severity. Disappears entirely when all systems are operational. Requires `curl`.

<details>
<summary>Code to add to <code>~/.claude/statusline.sh</code></summary>

Paste this block somewhere before your render section (e.g. just before the `ccusage` block):

```bash
# ---- claude platform status (background-cached, never blocks) ----
PLATFORM_STATUS_CACHE="/tmp/claude-platform-status.json"
PLATFORM_STATUS_MAX_AGE=300

_refresh_platform_status() {
  curl -sf --max-time 5 "https://status.claude.com/api/v2/summary.json" \
    > "${PLATFORM_STATUS_CACHE}.tmp" 2>/dev/null \
    && mv "${PLATFORM_STATUS_CACHE}.tmp" "$PLATFORM_STATUS_CACHE" 2>/dev/null \
    || rm -f "${PLATFORM_STATUS_CACHE}.tmp" 2>/dev/null
}

if command -v curl >/dev/null 2>&1; then
  if [ ! -f "$PLATFORM_STATUS_CACHE" ]; then
    (_refresh_platform_status) &
  else
    _cache_mod=$(stat -c %Y "$PLATFORM_STATUS_CACHE" 2>/dev/null || stat -f %m "$PLATFORM_STATUS_CACHE" 2>/dev/null || echo 0)
    _now=$(date +%s)
    if [ $(( _now - _cache_mod )) -ge $PLATFORM_STATUS_MAX_AGE ]; then
      (_refresh_platform_status) &
    fi
  fi
fi

platform_status_line=""
if [ -f "$PLATFORM_STATUS_CACHE" ] && [ "$HAS_JQ" -eq 1 ]; then
  _indicator=$(jq -r '.status.indicator // "none"' "$PLATFORM_STATUS_CACHE" 2>/dev/null)
  if [ "$_indicator" != "none" ]; then
    _incident=$(jq -r '[.incidents[] | select(.status != "resolved") | .name] | first // ""' "$PLATFORM_STATUS_CACHE" 2>/dev/null)
    _affected=$(jq -r '[.components[] | select(.status != "operational") | .name] | join(", ")' "$PLATFORM_STATUS_CACHE" 2>/dev/null)
    _msg="${_incident:-${_affected}}"
    [ -z "$_msg" ] && _msg="$_indicator"
    _ps_clr=""
    _ps_rst=""
    if [ "$use_color" -eq 1 ]; then
      case "$_indicator" in
        minor)    _ps_clr="$(printf '\033[38;5;222m')" ;;  # gold
        major)    _ps_clr="$(printf '\033[38;5;203m')" ;;  # coral
        critical) _ps_clr="$(printf '\033[38;5;196m')" ;;  # bright red
      esac
      _ps_rst="$(printf '\033[0m')"
    fi
    platform_status_line="⚠ ${_ps_clr}${_msg}${_ps_rst}"
  fi
fi
```

Then add this just before your `# LINE 3` / session time block to append the alert to your metrics line:

```bash
if [ -n "$platform_status_line" ]; then
  [ -n "$line2" ] && line2="${line2}  ${platform_status_line}" || line2="$platform_status_line"
fi
```

## Customizing

`statusline.sh` is plain bash. Edit it directly to change colors, remove sections, or add your own data sources.

- **Colors** are 256-color ANSI codes in the `*_color()` functions near the top of the script.
- **Sections** are assembled near the bottom in the render block; delete or reorder the pieces you don't want.
- **Data sources** follow one pattern: compute a value early, cache anything slow to a file, and only read the cache at render time. The platform-status and account blocks are good templates for adding something new.
- **Input** is the JSON Claude Code pipes to stdin on every refresh (model, cwd, transcript path, context usage, cost). To see exactly what your version sends, set `CC_STATUSLINE_DEBUG=1` in your environment; the script then appends each input to `~/.claude/statusline.log`. Logging is off by default because nothing reads that file and it grows without bound.

To start over from a freshly generated script:

```bash
npx @chongdashu/cc-statusline install --theme minimal
```

Run `npx @chongdashu/cc-statusline --help` to see all available themes and flags, then re-apply the snippets from [What's Custom](#whats-custom).

## Wrapping it: SpecSwarm users

If you use [SpecSwarm](https://github.com/MartyBonacci/specswarm), install the `ss-status` plugin on top of this:

```
/plugin install ss-status@specswarm-marketplace
/ss-status:install
```

It does not replace this statusline. It wraps it: `settings.json` is pointed at a small wrapper that renders this script at most once a minute from a per-session cache, and adds one extra line in SpecSwarm conduct projects (`🔨 building`, `💀 last build DIED`, `✓ builders idle — safe to close`) refreshed every 5 seconds. `/ss-status:uninstall` restores your previous setting exactly.

Because the wrapper calls `~/.claude/statusline.sh`, you can still update this script in place (or `./install.sh --link` it) and the wrapper picks up the change on its next cache refresh.
